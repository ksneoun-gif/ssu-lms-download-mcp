# 유세인트 시설 예약
현재 지원은 유세인트 화면을 사용하는 브라우저 방식이다. 별도 시설 예약 HTTP API는 제공하지 않는다.
1. https://saint.ssu.ac.kr/irj/portal 에서 현재 로그인 상태를 확인한다. 로그인 화면이면 사용자가 인증을 완료하도록 한다. 쿠키·비밀번호를 출력하지 않는다.
2. 시설사용 → 장소사용신청 → 장소예약 현황조회로 이동한다. 좁은 화면에서는 모바일 메뉴 박스를 사용한다. 실제 건물/강의실 목록과 날짜·시간을 선택해 조회한다. 슬롯 표시와 별도의 사용 제한 안내를 함께 확인한다. '예약가능' 셀만으로 신청 가능하다고 판단하지 않는다. 2026-10-07 검증에서는 10월 9일 셀이 '예약가능'이어도 공휴일 사용 제한 안내가 우선했다.
3. 신청 전 시설·사용일·시작/종료시간·인원·용도·신청자 구분 등 현재 폼의 필수 항목을 수집한다. 필요한 정보만 사용자에게 묻는다. 화면의 이용 규정을 매번 확인한다. 확인 당시 일반 강의실 규정은 사용일 14일 전부터 3일 전, 일요일/공휴일 불가, 금요일 12시 마감이었다. 이 값을 변경 불가능한 규칙으로 간주하지 않는다.
4. 장소사용신청(학생) 또는 운동장예약(학생)에서 해당 시설을 선택하고 폼을 준비한다. 구체적인 예약 제출 지시가 있을 때만 신청한다. 기능 추가·조회 요청만으로 시험 예약을 제출하지 않는다. 유료 사용, 약관 동의, 민감 정보 전송은 컴퓨터 사용 확인 정책을 적용한다.
5. 제출 응답과 진행현황에서 신청번호·시설·일시·승인 상태를 검증한다. '신청'을 '승인'으로 표현하지 않는다. 승인 후 사용허가서 출력 등 화면에서 요구하는 후속 절차를 안내한다. 취소는 대상 예약을 확인하고 사용자 지시에 따라 수행한다.
6. 중첩 iframe은 DOM의 실제 프레임을 사용한다. SAP 세션 URL이나 동작 요청을 추측·재사용하지 않는다. 폼에 저장된 연락처를 대화에 노출하지 않는다.
7. 내장 브라우저에서 SAP 중첩 프레임이 읽히지만 `Click target is no longer available` 또는 `Keyboard focus root is no longer available`로 조작이 실패하면 반복하지 않는다. 일반 Google Chrome을 cua.getApp으로 열고 새 탭의 정상 포털 주소에서 SSO → 시설사용 메뉴로 이동한다. Chrome 기본 접근성 조작으로 건물·강의실 선택과 조회가 2026-10-07 실제 검증됐다. 선택 후 SAP가 컨트롤을 다시 생성하므로 매번 최신 접근성 상태에서 새 요소 번호를 읽는다. 기본 접근성 클릭도 실패하면 최신 스크린샷의 좌표를 사용한다.
8. `500 Internal Server Error`는 위 조작 도구 오류와 구분한다. 같은 SAP 세션 URL을 독립 탭으로 열거나 예약 POST를 추측하지 않는다. 정상 포털 메뉴에서 다시 접근하고, 해결되지 않으면 막힌 단계를 보고한다. 조회 성공을 예약 제출·승인 성공으로 표현하지 않는다. 실제 제출은 아직 검증하지 않았다.
